# Děti — Family Schedule & Pickup Confirmation App

**Domain:** `deti.martinkalis.com` (Firebase Hosting custom domain, DNS configured later)
**UI language:** Czech · **Timezone:** Europe/Prague · **Status:** design finalized, awaiting seed data

## Purpose

A private family app that shows each kid's daily schedule and — as its core function —
tracks **who is picking up which kid today and confirms that it actually happened**,
shared between parents and grandparents.

## Users & Roles

| Role | Who | Can do |
|---|---|---|
| **Admin** | Parent(s), first sign-in = admin | Everything: edit schedules, events, holidays, members, settings |
| **Adult** | Grandparents, promoted parents | View all, claim pickups, confirm (incl. on behalf of others), edit day notes |
| **Child** | Kids (Google accounts via Family Link) | View everything, read-only. No push notifications |

- Sign-in: **Google account only** (Firebase Auth).
- Membership: **invite links** generated by an admin. New members join **unassigned**;
  an admin assigns the role (adult/child/admin) after joining. Unassigned users see a
  "waiting for approval" screen.
- Single family — no multi-tenancy.

## Kids & Schedules

### Kid 1 — school kid
- **Hour schedule** (rozvrh hodin) per weekday, display-only.
- Two pickup windows per day (placeholders until real times provided):
  - after lunch: **12:30–14:30**
  - afternoon: **15:30–17:00**

### Kid 2 — preschool kid (třída Ptáčci a Butterflies)
- Arrival (příchod): **7:30–8:45** (display-only)
- Pickup windows:
  - after lunch (po obědě): **12:40–13:00**
  - after snack (po svačině): **15:00–17:45**

### Shared schedule concepts
- **One pickup per kid per day.** The pickup window (lunch vs. afternoon) is chosen by
  the person **claiming** the pickup. Whoever picks up also takes the kid to any event that day.
- **Events**: manually entered (source: preschool online calendar, swimming, etc.).
  Informational, shown on day/week views. An event may carry an **adjusted pickup time**
  (e.g., leave earlier for swimming) which overrides the window for that day.
- **Schedule exceptions**: per-date or per-weekday overrides of normal times (shortened
  days, trips, lessons).
- **Holidays**: per-kid holiday calendars (date ranges with labels, provided by admin).
  Holidays and weekends = rest days: no pickup, no claims, no alerts; events still display.
- **Day notes**: one optional free-text note per kid per day ("vzít plavky"), editable by
  any adult, visible to all.

## Pickup Workflow (core feature)

1. **Claim** — any adult claims a kid's pickup for a day, choosing the window
   ("Beru Ptáčka po obědě"). Claims can be made any time in advance.
2. **Un-claim** — the claimer can cancel anytime → day reverts to unclaimed,
   push notification to all adults.
3. **Take-over** — another adult can directly take over a claimed slot; previous
   claimer is notified.
4. **Confirm** — at pickup, the claimer taps Confirm. **On-behalf confirmation** is
   allowed: any adult can confirm for someone else, recorded as
   "confirmed by X, picked up by Y".
5. **Log** — simple permanent history: date, kid, window, claimed by, picked up by,
   confirmed by, timestamps.

### Alert ladder (web push, adults only; all times/toggles configurable by admin)

| # | When | Condition | Recipients |
|---|---|---|---|
| 1 | 11:00 same day | nobody claimed today's pickup | all adults |
| 2 | 1.5 h before pickup window | still nobody claimed | all adults (urgent) |
| 3 | end of pickup window | claimed but not confirmed picked up | all adults |
| 4 | 1.5 h before claimed pickup | quiet nudge | claimer only |

Defaults: all four on. Unclaimed days assume the **afternoon window** for alert timing.

## UI

- **Today dashboard** (home): one card per kid — today's timeline (school hours,
  arrival, events, note), pickup status with big **Vyzvednout / Potvrdit** button,
  color state: 🔴 unclaimed → 🟡 claimed → 🟢 confirmed. Rest days marked "prázdniny/víkend".
- **Week view**: overview of both kids' events, claims and notes for the week.
- **Log**: pickup history list.
- **Admin**: schedules, events, holidays, exceptions, members & roles, invite links,
  alert settings, JSON export/import of all configuration data.

## Tech Stack

- **Next.js** (static export) + **Firebase**: Auth (Google), **Firestore** (real-time
  data), **Cloud Functions (scheduled)** for the alert ladder, **FCM web push**,
  **Firebase Hosting** at `deti.martinkalis.com`.
  - Note: scheduled Cloud Functions require the **Blaze** (pay-as-you-go) plan;
    at family scale the cost is ~0 Kč, but a billing account must be attached.
- **PWA**: installable to home screen, offline shell, push notifications.
- **Android APK later** (optional): TWA wrapper via Bubblewrap around the same deployed
  app — no second codebase; for grandparents who prefer a "real app". Web-first.
- **Data entry**: initial data seeded from configuration provided in chat; everything
  editable in the admin UI afterward; JSON export/import for backup/bulk edits.
- Firestore security rules enforce roles server-side (child/unassigned = read-only,
  schedule writes = admin only, claims/confirms = adults).
